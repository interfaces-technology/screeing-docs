title: 'POST /api/v1/auth/token — Sign In and Mint a Token Pair'
sidebarTitle: '/auth/token'
description: 'POST /api/v1/auth/token authenticates with email and password and returns a scoped device token pair — access (24h) and refresh (30d).'
---

Use this endpoint to exchange your email and password for a device token pair. The access token authenticates every subsequent API call; the refresh token lets you rotate both tokens before or after the access token expires without signing in again. Specify the `persona` field to scope the tokens to either filmmaker (`host`) or buyer (`watcher`) operations.

**Method:** `POST`  
**URL:** `/api/v1/auth/token`  
**Auth required:** None  
**Rate limit:** 10 requests per minute per IP

## Request body

<ParamField body="email" type="string" required>
  The email address associated with your Screening account.
</ParamField>

<ParamField body="password" type="string" required>
  Your account password. Minimum 8 characters, maximum 256 characters.
</ParamField>

<ParamField body="persona" type="string" required>
  The persona scope for this token pair. Must be `host` (filmmaker) or `watcher` (buyer). Both personas are open self-serve signup; host-scoped tokens still require an approved organisation before you can sell.
</ParamField>

<ParamField body="label" type="string">
  A human-readable label for this device or integration (e.g. `"My Server"` or `"CI Pipeline"`). Shown in the device list. Maximum 120 characters.
</ParamField>

## Response

A successful `200` response returns the token pair and expiry metadata.

<ResponseField name="accessToken" type="string">
  The Bearer token to include in `Authorization` headers. Prefixed `scr_live_…` on production or `scr_test_…` on preview/dev. Valid for 24 hours.
</ResponseField>

<ResponseField name="refreshToken" type="string">
  The single-use rotation token. Prefixed `scr_rt_live_…` or `scr_rt_test_…`. Valid for 30 days. Rotate with `POST /api/v1/auth/refresh`.
</ResponseField>

<ResponseField name="accessTokenPrefix" type="string">
  The first characters of the access token, useful for display and identification without storing the full value.
</ResponseField>

<ResponseField name="accessExpiresAt" type="string">
  ISO 8601 timestamp of when the access token expires (24 hours from mint).
</ResponseField>

<ResponseField name="refreshExpiresAt" type="string">
  ISO 8601 timestamp of when the refresh token expires (30 days from mint).
</ResponseField>

<ResponseField name="persona" type="string">
  The persona this token pair is scoped to — `host` or `watcher`. Matches what you passed in the request.
</ResponseField>

## Error codes

| HTTP status | Code | Description |
|-------------|------|-------------|
| `400` | `invalid_json` | The request body is not valid JSON |
| `400` | `invalid_body` | One or more required fields are missing or invalid |
| `401` | `invalid_credentials` | Email or password is incorrect |
| `403` | `forbidden` | Your account is not authorised for the requested persona (for example, no approved host organisation) |
| `429` | `rate_limited` | Too many requests from this IP — wait before retrying |
| `503` | `auth_not_configured` | Auth is not configured on this deployment |

## Example

<CodeGroup>

```bash cURL
curl -X POST https://usescreening.com/api/v1/auth/token \
  -H "Content-Type: application/json" \
  -d '{
    "email": "you@example.com",
    "password": "your-password",
    "persona": "watcher",
    "label": "My Integration"
  }'
```

```typescript TypeScript
const res = await fetch('https://usescreening.com/api/v1/auth/token', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    email: 'you@example.com',
    password: 'your-password',
    persona: 'watcher',
    label: 'My Integration',
  }),
});

if (!res.ok) {
  const { code, message } = await res.json();
  throw new Error(`${code}: ${message}`);
}

const { accessToken, refreshToken, accessExpiresAt } = await res.json();
```

</CodeGroup>

**Example response:**

```json
{
  "accessToken": "scr_live_xxxxxxxxxxxxxxxxxxxxxxxxxxxx",
  "refreshToken": "scr_rt_live_xxxxxxxxxxxxxxxxxxxxxxxxxxxx",
  "accessTokenPrefix": "scr_live_xxxx",
  "accessExpiresAt": "2025-01-16T12:00:00.000Z",
  "refreshExpiresAt": "2025-02-15T12:00:00.000Z",
  "persona": "watcher"
}
```

<Warning>
  Store both tokens securely — they are shown only once. If you lose your refresh token before it expires, you must sign in again with `/api/v1/auth/token` to mint a new pair.
</Warning>
